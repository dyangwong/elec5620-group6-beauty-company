# 拟定协作流程

中文阅读副本，依据 2026-10-16 英文主版同步。以[英文主版](../COLLABORATION.md)为维护依据；若有歧义，按英文主版及其来源优先级处理。编号、状态、路径和命令保持原值。正文中的代码路径均相对仓库根目录。

按 Danny 要求和 Stage 1 映射准备，不证明全员采纳。公开 GitHub 基线与 main 保护已上线；
Jira KAN 已有六个 Epic/五份任务，GitHub 邀请与成员实际工作仍分开处理，见 docs/JIRA.md。入口、team.json、tasks.json、任务书和共享文件规则定义开工流程。

## 追踪一个工作单元

真实 Jira 任务关联 Stage 1 需求/功能、用例、模型/guard、验收。分支/PR 关联任务，记录实现、
测试、观察结果、反馈、剩余限制。实际 key 可用后再填；占位不是任务。
Jira 管工作/迭代，GitHub 管代码/审阅/CI，避免两边维护冲突的需求。

保留一个集成分支 `main` 和短任务分支。尽量做包含领域逻辑、相关界面、证据的纵向工作，
不只做孤立页面。当前默认延续五条责任链；成员明确声明身份、查实际认领，不替他人暗中认领。
首批 helper 只准备本地包。

维护者先发布一个共同初始提交再让队友 clone。下载目录或没有 HEAD 的本地仓库都不是共同分支基线。
检查分支/脏文件、保留无关工作，使用任务分支。共同初始提交现已发布，较早开工准备本身没有发布。

没有 Jira connector 时，获授权者可手动认领/更新。共享追踪未建立前可独立本地分支工作，
如实记录没有共享认领；共享 PR 集成前关联实际事项、核对重复认领。不造编号或迭代历史。

## 共享变更

- 任务列出允许模块/文件与明确需求版本。
- 契约变更同步调用方、接收方、保存、样例、测试、文档。
- AP/CO 与数据库结构变更列明受影响链及审阅人。
- 保留其他成员工作，合并前核对当前变更。
- 作者可自行检查并合并已通过检查的 PR，不强制他人批准。共享接口/结构/权限变化请相关人审阅；AI 生成不等于审阅/贡献。
- 测试与风险匹配，不写只复述实现的测试。

## 任务完成定义

1. 声明的验收条件有可观察证据，区分 mock/live。
2. 相关失败、范围、重复效果检查及基线通过。
3. 启动、改动的 API/UI 有文档与验证。
4. 追踪表区分完整验收组与子集。
5. PR 解释行为、证据、偏差、剩余风险；实际审阅/Jira 操作发生后再记录，不本地编造。

## 迭代与评分证据

真实发生时保留规划决定、迭代目标、可演示增量、老师/队友反馈、修改和复盘。
Jira 应体现过程，而非最后一次性标 Done。不在此创建固定 sprint 日程，团队按可用时间决定。
贡献表描述每人具体工作，每评分行比例合计 100%。AI 辅助、集成、测试、审阅、文档如实说明，
提交数不等于贡献，此处不分配比例。

## 源码交付

在明确版本导出干净源码，排除 var/、.git、凭据、机器状态。从实际 Canvas 提交下载，
在新目录演练启动；托管演示/现成 checkout 不能替代此验证。向教学团队确认现场 Python、安装、
联网规则，不隐藏依赖原始目录、外部模型或缓存服务。

当前 Git 规则见 [GIT_WORKFLOW.md](GIT_WORKFLOW.md)：必须 PR/检查，不强制他人批准，不直接或强推 main。上文开工时的状态属于准备记录，不能当成当前托管证据。

当前配置见 [JIRA.md](JIRA.md)，计划分配不等于本人认领或完成；上文未连追踪系统的说明仅适用于没有可用 Jira 连接的成员。
