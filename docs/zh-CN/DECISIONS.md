| 决定 | 理由与限制 |
|---|---|
| 新独立项目，旧作仅参考 | 凭据、数据、无关商业范围留在仓库外，无复制旧文件。 |
| 模块化单应用、单本地库 | 保留五条链边界、减少初期集成/设置成本，不是五个独立微服务。 |
| 无构建 HTML/CSS/JS + Python 标准库 | 现有 Python 3.9 可离线运行，无需安装。只是初始交付选择，不代表先进技术得分；框架迁移仍可讨论。 |
| 浏览器 Customer/Founder 工作区 | 审批和跨角色证据可见。Stage 1 未定物理托管；未做微信专用交付，团队采纳待确认。 |
| 服务端演示会话/归属检查 | 避免旧作由客户端给用户/管理员身份；共享密码/本机 HTTP 不是生产身份。 |
| 确定性 mock 模型/媒体/商业适配器 | 可重复联调和故障注入，不证明真实 LLM/Agent 能力或视频生成。 |
| AP 决定提交与投递分开 | 投递失败不抹掉决定，重复投递不执行业务。 |
| 模拟外部效果与 CS 结果分开提交 | 验证写后超时/保存恢复；真实外部语义未核实。 |
| 可选功能 OFF/未实现 | 初期聚焦核心集成/安全，五个编号仍保留。 |
| 沿用 Stage 1 负责人作默认映射 | Danny 要求据此开工，五份首批任务已备；不推断个人认领/接受/完成。 |
| 公开版改用完整脱敏阅读副本 | 公开发布时替代原字节一致打包决定。保留 63 页/模型，仅去学号/元数据；原件留本地且忽略，分别记录原件与副本哈希。 |
| 暂缓真实/本地模型 | 用户要求先不急，任务用注入的确定性样例，不下载、不选供应商、不索 key、不配硬件。 |

## 仍需团队决定或更多证据

- 采纳/修改正式 Stage 1 依据、相关负责人的接受。
- 默认映射的实际接受/认领、GitHub 账号、Jira 设置、不同工具如何加载规范；仓库公开已由 Danny 后续明确选择。
- 保留当前网页栈、加入框架或微信交付；迁移前记录对现有 API/模型的成本。
- 真实 LLM、工具、资金/key、guard/事实验证。
- 视频/媒体方案与允许的标注替代；分镜卡不能报告为完成生成视频。
- 明确 PoC 政策、风险、新鲜度、过期、质量标准及批准。
- 生产身份/保留、托管演示，不在初期范围。
- 剩余需求、全部可选 ON 行为、完整验收、真实 Agile、干净 Canvas/现场演练。

不从旧原型推断退货期、置信度、金额风险阈值、审批期限。商品值/资格都是虚构样例。

## 公开 Git 协作 · 2026-10-16

Danny 明确要求普通公开仓库、无 Pro、宽松审阅。main 必须 PR/CI，通过后作者可自行检查并合并，
不强制他人批准。共享接口/结构/权限变更请相关队友审阅，不能将自行合并写成他人审阅。
公开不自动等于采用开源许可证。原始学号、凭据、运行数据不发布。
